# October 2026 provenance review

Reviewed on 2026-10-02. The project remains a build-free, client-side application.

## Implemented

- Share the IPTC source-type vocabulary between metadata and C2PA verification.
  Only trained generative media and generative editing count as explicit AI types.
- Preserve non-generative source types in C2PA details, without AI verdicts.
- Exclude ingredient source types from active-image attribution.
- Recognize Seedream / Doubao / Jimeng, Qwen-Image / HunyuanImage, ChatGPT and
  Nano Banana names in generator fields. Decode UTF-8 for Chinese byte clues.
- Keep byte statistics informational. Compressed bytes are not RGB pixels,
  and neither their distribution nor a keyword confirms an invisible watermark.
- Correct the SynthID FAQ and remove unsupported watermark-removal claims.
- Read Chinese AIGC declarations from JPEG / PNG / WebP metadata, preserving
  the three label levels and producer / propagator fields in cards and reports.
  See [AIGC parsing details](AIGC-METADATA.md) for bounds and unsupported formats.
- Use the shared tool/source-type helpers in the metadata tab, remove the
  camera-EXIF authenticity score, and expose AIGC declarations there too.
- Separate C2PA integrity and signer trust in metadata details, localize the
  metadata tab, and tolerate malformed GPS fields, history items and dates.
- Escape quotes in HTML attributes, including user-controlled batch filenames.

## Primary references

- [IPTC Digital Source Type](https://cv.iptc.org/newscodes/digitalsourcetype/):
  normative distinctions between trained generation, editing and ordinary algorithms.
- [Google Gemini image verification](https://blog.google/innovation-and-ai/products/ai-image-verification-gemini-app/):
  official SynthID verification, distinct from this app's local heuristics.
- [Volcengine image generation documentation](https://www.volcengine.com/docs/86081/1804467):
  vendor API metadata configuration is distinct from the stored GB / TC260 label.
